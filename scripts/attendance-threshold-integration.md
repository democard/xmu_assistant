# 双端签到人数门槛与页面接入交接

日期：2026-09-20。基线 `c3012b5`，开发分支 `feature/attendance-progress`。

## 用户确认的功能

- 自动签到支持三种模式：不等待人数条件、已签人数达到 N 人、已签比例达到 X%。人数和比例均由用户填写，不写死为参考项目的 15%。
- 人数条件和原有自动签到开关独立。PC 沿用总开关，Android 沿用数字 / 雷达各自的开关；只有自动处理已开启、类型支持、达到所选条件时才允许自动提交。主动手动操作沿用原本的用户控制。
- 数据读取失败或名单不完整不能当作 0% 或已达标；统计不能使用“历史未知显示已签”的 UI 回退。
- Android 进行中记录右侧显示人数与比例，数字码放卡片底部并可复制；已结束的数字签到在右侧人数、比例下面追加签到码，不替换统计。雷达和二维码不显示数字码。
- PC 沿用桌面表格和策略页，提供同样的统计、数字码与门槛配置；不把手机卡片照搬到桌面。
- 读取人数、获取数字码和刷新页面都是只读行为，不得调用签到提交接口。

## 核查发现的缺口

1. 两端已有纯统计解析与模拟样例，但尚未接到正式界面或自动签到决策。
2. 旧去重以“已见过/已处理”表示整个事件生命周期，未达门槛时如果照旧记入去重集，以后达到门槛也不会再次判断。提醒与完成必须分开处理。
3. PC 原先的延迟任务未在提交前核实最新门槛、活动存在性及运行代数，不能直接在界面上增加一个输入框后沿用旧提交路径。
4. Android 的后台只检查数字/雷达开关；原配置没有门槛持久化字段。
5. 旧截止时间占位未必有数据来源。参考项目的[公开响应样例](https://github.com/vintcessun/xmu_assistant_sign_bot/blob/a9b0c2c1162f5a4fe503c6d76186a0b201e2d4c8/src/api/xmu_service/lnt/rollcalls.rs#L86-L90)只有开始时间和是否结束，不能凭此推算倒计时。Android 对空值、空格日期及现有备用字段也需要补齐处理。

## 共同行为约定

- 模式值 `none` / `count` / `percent`。升级默认 `none`，不擅自改变原有自动签到行为。示例默认数值 5 人、15% 仅为未启用输入值，用户可修改。
- 人数为正整数，比例为 1–100 的整数百分数。
- 人数按 `present >= N` 判断；比例按 `present * 100 >= total * X` 判断，不用四舍五入后的显示值，也不先做整数除法。
- 未达标继续正常监控，不为每条记录另起高频轮询；已提醒不等于已完成，达标后防重复提交。
- 监控轮次内按活动签到读取明细，因此相较原来只查活动列表会增加明细 GET。一次明细同时提供人数、本人状态与数字码，避免为三个字段分别请求；历史统计复用原有本人明细核实请求。
- 提交前尊重最新设置、账号和监控运行状态；已签、已结束、停止监控、退出或切换账号应阻止旧任务继续处理。
- 普通只读明细失败只影响对应记录；会话过期走现有恢复/停止语义。
- 页面缺失态使用“签到进度 / 暂未获取”，不能写成容易被理解为全员到勤的“全班已签”。历史数字码能读取才展示，缺失不补造。

## 共同验收样例

`android/app/src/test/resources/attendance_threshold_reference_cases.json` 包含 21 个合成案例，由两端测试共同读取：5/40 与 6/40 的 15% 边界、1/7 与 1/6 小班、199/200 不得按显示舍入视为 100%、自定义人数/比例、空或不完整名单、不启用门槛时的兼容性，以及大计数乘法。

已覆盖未达→达标→再次轮询、提醒去重、配置保存重读、停止/换号/条件修改、缺码继续等待、只读请求和手机卡片尺寸。PC 额外覆盖策略修改时旧提交仍在途，不能并发启动第二笔；Android 覆盖写回执不明后只有明确未签才允许有限重试。

## 使用位置与后续维护

- Windows：策略页的“自动签到等待条件”选择人数或比例，填写数值并确认更改；首页原有“开启自动签到”总开关仍决定是否允许自动处理。
- Android：更多 → 策略 → 自动处理时机，选择达到人数或达到比例后填写数值并保存；数字 / 雷达自动处理开关分别生效。
- UI 统计对应本次点名的名单，不以课程选课人数代替分母；未知或不完整名单用缺失态展示，不猜测全班人数。
- PC 历史沿用 `RECENT_VERIFY_LIMIT=20` 自动补充最近记录的明细，较老记录显示“未获取”，用户可点“核实所选”；CSV 同步包含人数、比例和数字码。Android 沿用最近十次历史。
- 通用边界样例放在 Android 测试资源目录，Python 测试读取同一份 JSON。变更人数语义时需同时跑两端测试。
- 人数条件只影响自动提交，不会把读取统计、复制数字码或手动刷新变成提交操作。历史缓存仅新增汇总计数和数字码，不保存整班学生名单。
