# 数字签到接口兼容（1.7.4）

旧明细接口 `GET /api/rollcall/{id}/student_rollcalls` 可能成功返回 JSON，但 `number_code` 为 null。双端仍用该明细核实本人状态和人数；数字码缺失时只读补查：

`GET /api/timetable_rollcalls?course_ids={course_id}&rollcall_date=YYYY-MM-DD`

日期按签到开始时间转换为 UTC 日期，不是界面上的北京时间。例如虚构时间 `2026-06-04 07:48:00+08:00` 对应查询日期 `2026-06-03`。仅有截止时间或正在监控且没有开始时间时，最多查询该 UTC 日期及前一天。

只从返回 `rollcalls` 中与目标签到 ID 完全一致的记录读取直接数字码字段；返回课程 ID 存在时也必须一致。不会递归从别的活动或学生记录借码。码按字符串传递，保留前导零。缺课程 ID 的监控活动仅在本账号课程列表中按唯一课程名匹配，重名或缺上下文时保持未知。

日期接口只补数字码，不覆盖旧明细的学生名单、本人状态、人数或活动结束判断。403、非 JSON 和普通网络失败保持未知；401、已识别登录页和身份域重定向继续按会话失效处理。桌面监控在只读请求返回后检查暂停标记，不继续发补查请求；Android 沿用当前监控令牌和提交前检查。

提交保持 `PUT /api/rollcall/{id}/answer_number_rollcall`，JSON 仍为 `deviceId` 与字符串 `numberCode`。找不到对应数字码则不提交；维护侧测试没有向真实签到发送 PUT。

Windows 每轮查询以新结果覆盖码缓存，缺失时立即清空旧码。延迟提交前重新查询失败或无对应码时也不复用先前值，继续等待后续有效结果。已有自动提交失败后不自动重试的行为保持不变。

Windows 覆盖监控、最近记录核实、手动核实、提交前复核及 `send_code` 兼容入口。Android 覆盖共享页面/监控查询、历史记录及 `answerNumber` 入口。实现分别在 `number_code.py` 与 `RollcallNumberCodeLookup.kt`。

离线回归覆盖旧码优先、null 补查、严格 ID/课程匹配、前导零、UTC 跨日、权限/会话错误、旧缓存失效和只补码不推断到勤。测试使用虚构标识、数字码和传输，不访问真实账号。活动发现接口仍保留 `/api/radar/rollcalls`；结束后的空列表不足以判断该接口对进行中活动失效。

2026-10-10，用户反馈现有 Android 1.7.4 APK 可以完成实际数字签到。此反馈不代表 Windows、雷达签到、长期后台运行或全部设备均已验证，详见 [1.7.4 验证记录](verification-1.7.4.md)。
