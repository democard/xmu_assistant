## 复现与修复

| 模块 | 触发与实际影响 | 修复机制 |
| --- | --- | --- |
| Android 排名 | 请求门先取得、协程尚未调度便取消，后续请求一直被判为进行中；客户端工厂抛错同样漏门 | 门释放绑定任务完成回调，初始化放入受保护协程并恢复错误 / loading 状态 |
| Android 排名 | Cookie 从 IO 收尾写回，登出或换号可插在检查和写入之间；保存失败跳过后续释放 | 在 Main 同线程接纳 Cookie，与 UI 会话清理顺序一致；保存异常与 loading / 请求门清理隔离 |
| Android 课件、历史签到、考试 | 下载、历史查询、空学期探测、变化检查、静默刷新在已取消作用域中发起，协程体没有执行，body-finally 也没有释放门 | 普通请求统一绑定完成回调；考试探测向后续 fetch 移交时单独记录所有权，探测任务完成后继续持有 fetch 的门 |
| Android 启动缓存 | IO 读取旧账号缓存期间登出或切换到空缓存账号，原来的“仍为空”判断再次成立，旧数据重新进入 UI / 进程缓存 | 启动读盘前记录缓存修订号，Main 接纳前复核；登出、换号清理和新刷新都会推进修订号，淘汰旧恢复结果 |
| Android 后台课表 | Worker 更新文件和小组件，但同进程课表快照仍旧；Activity 重建优先复用旧快照，再次把小组件回滚 | 后台提交同步更新进程快照，并以持久化修订号约束发布顺序，保护并行前台更新 |
| Android 手动周次 / 小组件 | Worker 已进入本地写入时，手动校准先发布进程快照、后推进版本，可能被旧 Worker 覆回；快照和 Widget 分开发布也会让晚到的旧 Widget 超过新手动同步；Worker 在手动写入预留版本后读取旧文件，若该写先完成，已读取旧日历的 Worker 仍可能使用相同 revision 覆写它；Activity 取消还可能丢弃排队快照 | 手动写入先预留版本；待落盘的前台快照未完成时，Worker 不得接替版本；完成当前 reservation 时推进版本，使期间捕获版本的 Worker 失效；已接纳的文件快照以原子启动完成持久化，即使作用域在调度前取消；手动校准 / 恢复先推进持久化版本再发布快照；Worker 在同一本地锁内核验版本、发布快照及 Widget，锁内没有网络请求或等待 Main |
| Android 教务持久化 | 旧课件写缓存已经通过准入但尚未 apply，登出先清除后旧任务再次提交 | 清理先推进进程修订号，再等待已准入的本地写完成，随后清除 JSON，阻止旧任务复活缓存 |
| Windows 课件 | A 课程正在读取时选 B，A 成功会追赶 B，A 失败却没有课程标识，B 一直不加载 | 错误事件携带课程 ID；对仍有效会话，旧课程失败结束后自动读取当前选择；兼容原事件格式 |
| Windows 课件 | 课程列表、详情或下载线程启动失败，进行中标记 / 下载状态一直残留，恢复线程后也持续阻塞重试 | 在入口处理启动异常，按原账号 / 会话提交错误回填，恢复任务标记与下载 UI，保持线程启动函数原有抛错契约 |

## 复跑

仓库根目录执行：

```powershell
python -m pytest tests -q --tb=short
python -m ruff check xmu-rollcall-cli tests scripts
python -m compileall -q xmu-rollcall-cli tests scripts
cd android
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug --no-daemon --rerun-tasks --console=plain
```

Android 使用 JDK 17 和 SDK 35。依赖已完整缓存时可加 `--offline`。本轮构建启用 `--rerun-tasks`，以实际执行全量测试和构建，不复用上一轮任务结果。
